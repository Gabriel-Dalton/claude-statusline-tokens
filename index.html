Token counts and dollar cost in your Claude Code status line.

Anthropic's status line shows rate-limit percentages. statusline-tokens adds the numbers underneath: raw tokens and API-priced cost for the rolling 5-hour and 7-day windows, plus the Fable 5 weekly limit Claude Code never sends to a status line at all.

What it adds

The number you actually need is missing.

Claude Code reports rate-limit percentages. Other status-line packages mirror them. None of them tell you what the session is costing you.

$

API-rate cost

Dollar cost for both windows, priced per model family with the correct input, output, and cache rates.

F

Fable 5 weekly limit

The premium-model window Claude Code meters separately, and does not send to any status line. Fetched from the endpoint /usage reads, so you see it coming. How it works.

#

Raw token totals

Actual tokens consumed in the 5-hour and 7-day windows, summed locally from your transcripts.

@

Reset countdown

Every window says when it frees up: resets 2h14m @ 12:38pm PDT. The zone is resolved for the reset instant, so a reset past a DST cutover reads correctly, and it survives renders where Claude Code sends no rate-limit data at all.

Headroom

The number changes color before you hit a wall.

The 5h and 7d percentages come straight from your signed-in Claude account. It is the same number Claude Code uses to throttle you. The status line tints it so you read the band, not the digits.

Want different bands? Set STATUSLINE_PCT_THRESHOLDS to a warn,crit pair before Claude Code starts. For example, STATUSLINE_PCT_THRESHOLDS=65,85 shifts yellow to 65% and red to 85%. The defaults are 50,80.

New in v0.5.0

The Fable 5 limit no status line could show.

Claude Code meters premium models on a weekly window of their own, separate from your plan-wide weekly limit. Run out of it and Fable is gone for the rest of the week while 7d still reads 25%.

The hook payload cannot carry it. Claude Code assembles the status line's rate_limits object from five_hour and seven_day and nothing else. The Fable window is live in the same process, read straight off the anthropic-ratelimit-unified-* response headers alongside the Opus and Sonnet buckets, and none of them are forwarded. No way of parsing the hook JSON will surface it, which is why no status line has shown it, this one included until now.

So it is fetched the same way /usage gets it: GET /api/oauth/usage, where the window arrives as a limits[] entry with kind: "weekly_scoped". The segment is built from whatever scoped windows your account actually has, so a second one appearing server-side shows up without a code change, and an account with none renders nothing.

Your prompt never waits on it. The render reads a small cache file; when that cache ages past its TTL the render spawns a detached process to do the fetch, and the result lands on the next render. An atomically created lock file means ten open Claude Code windows still make one request between them.

  1. 01 Read the cache One small file. No network call on the render path, ever.
  2. 02 Take the lock, or move on One fetch per interval across every open window; an orphaned lock clears after 120s.
  3. 03 Fetch detached Token held in memory for the request only. Expired token? No request at all.
  4. 04 Degrade honestly Older than three hours renders --% rather than passing a stale number off as current.
The one part of this status line that leaves your machine, and it goes to Anthropic's own endpoint: no third party, no telemetry. The token is never logged or cached; only percentages and timestamps are written to disk. The same reply also carries the 5-hour and weekly figures, which are kept as a fallback for windows that have been idle too long to have heard anything themselves. Set STATUSLINE_SCOPED_LIMITS=0 to switch the segment, the cache and the request off in one go, STATUSLINE_SCOPED_TTL to change the 900-second idle interval, or STATUSLINE_SCOPED_ACTIVE_TTL to change the 90-second one used once that model has actually run.
Install

Three commands. Roughly thirty seconds.

First time touching Claude Code? Follow the guided path. setup.ps1 does the file copy, the JSON merge, and a smoke test for you. No Node, no npm, no extra tools.

Before you start
  • Claude Code is installed and you've had at least one conversation in it. That conversation creates the ~/.claude/ folder we'll be writing into.
  • PowerShell 7+ recommended. Open a terminal and run pwsh -v. If it errors, run winget install Microsoft.PowerShell. Windows PowerShell 5.1 (the one preinstalled on Windows 10/11) also works.
  • Git on your PATH. If git --version works in PowerShell, you're set. Otherwise grab it from git-scm.com.
  1. Step 01

    Clone the repo

    Anywhere on disk. The cloned folder is throwaway; setup.ps1 copies out the files it needs.

    git clone https://github.com/Gabriel-Dalton/`
  claude-statusline-tokens
  2. Step 02

    Run the setup script

    Copies the scripts to ~/.claude/, shows the JSON it wants to add to settings.json, and asks Y/n before it writes. A backup is saved first.

    cd claude-statusline-tokens
.\setup.ps1

    Tip Curious before committing? Run .\setup.ps1 -DryRun first. It prints the exact diff without touching anything.

  3. Step 03

    Open a new Claude Code window

    The status line shows up on the next prompt. The current conversation won't pick up the change; you need a fresh one for the new settings.json to load.

    # first render
cold  ~1.0s   # PS startup + scan
warm  ~0.3s   # cached, <20s old
Prefer to wire things up by hand?

If you'd rather edit settings.json yourself, the manual path lives in the README's manual install section. It's three steps: copy the .ps1 next to settings.json, paste a statusLine block in, restart.

On macOS or Linux?

The scripts run under pwsh (PowerShell 7+) on Unix too. Same three commands, but install pwsh first via your package manager (brew install powershell on macOS, your distro's repo on Linux), then clone and run ./setup.ps1.

Something went wrong?

The README's troubleshooting section covers the three or four ways this can fail: execution-policy blocks, mojibake characters, empty ~/.claude/projects/, and a malformed settings.json falling through silently.

Methodology

How the numbers are computed.

For every .jsonl line that carries a "usage" block in ~/.claude/projects/**/*, the script applies the following procedure.

The percentages are not computed locally. They come straight from rate_limits.five_hour.used_percentage and its 7-day sibling. These are the same authoritative numbers Claude Code uses internally for throttling decisions.

The token totals beneath them are summed locally, exactly the way ccusage does it: a recursive scan of every transcript, regex-extracted, deduplicated by message.id, windowed by ISO timestamp.

Cost is computed per turn, using the actual model family detected on that transcript line (Opus, Sonnet, or Haiku), with the correct input, output, and cache rates. Ephemeral cache creation bills at the 5-minute rate when the breakdown isn't exposed, which is the API default for unflagged blocks and the cheaper of the two tiers.

  1. 01 Parse timestamp Skip the line if it's outside the 7-day cutoff.
  2. 02 Dedupe by message.id Assistant turns log once per content block; raw summation would triple-count.
  3. 03 Sum the four fields input + output + cache_creation + cache_read.
  4. 04 Price it Detect model family on this transcript line; apply the matching API rate.
  5. 05 Window the totals Add to 7d. If the timestamp also clears the 5-hour cutoff, add to 5h.
Field-level regex extraction is ~10× faster than ConvertFrom-Json per line on a 20 MB transcript pile. A 20-second JSON cache keeps the bar snappy on every re-render.
Questions

The ones everybody asks.

Mostly about that alarming number in the middle of the bar.

How do I see token usage in Claude Code?

Claude Code's own status line reports rate-limit percentages but not raw token counts. statusline-tokens reads the transcript files Claude Code already writes to ~/.claude/projects/ and sums the usage block on every assistant turn, so the bar shows token totals for the 5-hour and 7-day windows next to the percentage.

Why does it say I used over 100 million tokens in one day?

Because roughly 97% of that number is cache reads. Every turn re-sends the entire conversation to the model, and those replayed tokens are billed and counted each time.

A real measurement from a 5-hour session: 168.2M tokens total across 827 assistant turns, of which 164.4M was re-read context and only 3.8M was genuinely new work: the words the model actually wrote, plus what was newly sent. The arithmetic that confirms it is 827 turns × 198.8k average context = 164.4M.

The number is real. It is just the same conversation being read over and over, not 168 million tokens of new material. Run scripts/verify-tokens.ps1 to reproduce that breakdown on your own transcripts.

Is the dollar figure my actual Claude bill?

No. It is what the same work would have cost at Anthropic's published API rates. On a Claude Pro, Max, Team or Enterprise plan you pay a flat subscription no matter what the bar says. Read it as an intensity signal, not an invoice.

When does the Claude Code 5-hour limit reset?

Claude Code hands the reset timestamp to the status-line hook as a Unix epoch. The bar renders it as a countdown plus a local clock time and its zone, resets 2h14m @ 12:38pm PDT, on both the 5-hour and 7-day windows, so you can see whether to push on or take a break.

Which models does the pricing cover?

Claude Fable 5 and Mythos 5 at $10/$50 per million tokens, the current Opus line (Opus 5, 4.8, 4.7, 4.6, 4.5) at $5/$25, older Opus (4.1, 4.0, Opus 3) at $15/$75, Sonnet at $3/$15 and Haiku at $1/$5. Each turn is priced using the model recorded on that turn, so a session mixing models still totals correctly.

Does it work on macOS or Linux?

It is PowerShell and targets Windows. PowerShell 7 runs on macOS and Linux and the transcript format is identical there, but the paths and the install flow are Windows-first and the other platforms are not currently tested.

How do I see my Fable 5 weekly limit?

Claude Code meters premium models on a weekly window separate from your plan-wide weekly limit, and /usage draws it as its own bar. It is not in the status-line hook payload, which carries the five_hour and seven_day buckets and nothing else, so no status line can read it from the hook.

This one fetches it from the endpoint /usage itself uses and renders it as a fable 61% segment with its own reset countdown. The fetch happens in a detached process every 15 minutes, so your prompt never waits on the network. Full detail here.

Does it send my data anywhere?

It sends no data anywhere, and there is no telemetry or third party involved. Every segment but one reads only files already on your disk.

The exception is the Fable 5 limit, which exists in no local file: that makes one GET to Anthropic's own usage endpoint every 15 minutes, the same one /usage calls, using the credentials Claude Code already stores. The token is never logged or written to disk; only percentages and timestamps are cached. Set STATUSLINE_SCOPED_LIMITS=0 and it makes no network calls at all. It is a single PowerShell file you can read end to end, MIT licensed.
